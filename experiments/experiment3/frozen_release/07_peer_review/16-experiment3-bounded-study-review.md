# Peer review — Experiment 3 Bounded Cloud Closure v1, and paper draft v0.3.1

**Verdict: accept. This is the strongest package Project Montecito has produced,
and the first one I was able to re-run end to end.** Every scientific number
reproduces. Four findings follow; two should be fixed before publication, none
changes a result.

---

## 1. What I did

Unlike previous rounds, this package shipped code *and* data, so the review is a
genuine replication rather than an arithmetic check:

1. verified all 51 package checksums;
2. confirmed the protocol SHA-256 recorded in the execution log matches the
   protocol file, so the CUE/Poisson seeds provably derive from a pre-frozen
   protocol;
3. audited every runtime module line by line;
4. checked the collision decomposition against brute-force enumeration;
5. recomputed the homometric control independently at 90 decimal digits;
6. **deleted the results and re-ran the whole pipeline from a clean copy.**

## 3. Findings

### 3.1 Two shipped result files cannot be regenerated by the shipped code

`group_summary.csv` and `mu4_difference_decomposition_vs_cue.csv` are **read** by
`make_paper_figures_v1.py` and **written by neither** shipped script. Re-running
the package therefore fails at the figure stage.

Worse in one respect, better in another:

- `group_summary.csv` is loaded into `SUM` and then **never used** — a dead read
  that nonetheless crashes the script when absent;
- the *contents* of both files are correct. I reconstructed both from my re-run's
  `all_window_endpoints.csv` and every value matches to all printed digits, with
  the additive identity `raw = pair + gt2` closing to 1e−16.

So this is a packaging gap, not a numerical one — but the package claims full
reproducibility, and as shipped it does not have it. **Fix: add the aggregation
step to the runner, or drop the unused `SUM` read.**

### 3.2 The reconstruction check is vacuous

`q4` is computed as the residual

    q4 = direct − c − 6·s2 − s4 − 4·t3 − w30 − w31

and `reconstructed_numerator` then adds those same terms back. So
`reconstruction_error ≡ 0` identically, and `reconstruction_passes()` cannot fail.
I confirmed this by corrupting `K[3,7]` by 0.37: the error stayed at `0.000e+00`
and the check still passed.

It appears in the results as `reconstruction_relative_error: 0.0` and is listed
among the package's integrity artifacts. **It provides no assurance whatsoever.**

*Mitigating:* the decomposition is nonetheless correct — I verified all six terms
including `Q₄` against brute force — so the vacuous check concealed nothing.
**Fix:** either compute `Q₄` independently on small cases and compare, or remove
the check from the reported integrity list rather than presenting it as evidence.

This is the same failure mode as the Experiment 2 pair bridge: a check that
compares a quantity with its own definition.

### 3.3 The unit tests are not shipped

`unit_test_log.txt` records `7 passed in 0.21s`, but no test module is in the
package. The claim is unverifiable, and `05_integrity` does not cover it. Ship the
tests or drop the log.

### 3.4 Two different σ scales are in play, and the paper uses the weaker one

The paper §6.1 reports the 10²¹ differences as "0.23, 0.13, and −0.09 CUE **window**
standard deviations". The bootstrap in `descriptive_comparisons.json` is instead
over 16-window **means**, whose sd is 4× smaller. Both are correct; they measure
different things. But they diverge sharply:

| dataset | moment | difference | z (window) | z (mean) | bootstrap tail |
|---|---|---:|---:|---:|---:|
| first 10⁴ | `μ₂` | −0.02984 | −1.34 | **−5.38** | 5e−5 |
| first 10⁴ | `μ₄` | −0.28492 | −1.40 | **−5.60** | 5e−5 |
| first 10⁴ | `μ₄^(>2)` | −0.07977 | −1.17 | **−4.67** | 5e−5 |
| near 10¹² | `μ₂` | +0.01069 | +0.48 | +1.93 | 0.053 |
| near 10¹² | `μ₄` | +0.08947 | +0.44 | +1.76 | 0.079 |
| near 10²¹ | `μ₄` | +0.02601 | +0.13 | +0.51 | 0.609 |

A reader who takes the window scale at face value would read the low-height effect
as "about 1.3σ — not much", when the inferential comparison the package itself
runs puts it beyond the 20,000-draw bootstrap resolution. **Report both scales
explicitly, or use the mean scale consistently and say so.**

## 4. One scientific note

**The paper flattens a distinction the closure report makes.** Paper §6.1 says "the
two high-height samples lie near the finite CUE means." But D1 (10¹²) is displaced
positively on **all four** moments, with `μ₂` and `μ₄` at ~1.8–1.9 mean-sd and
bootstrap tails of 0.053 and 0.079 — the largest non-D0 signal in the study and
consistently signed. D2 (10²¹) is genuinely null (tails 0.36–0.71).

The closure report already grades these differently —
`D1 … = BROADLY_SUPPORTED` versus `D2 … = SUPPORTED_WITHIN_BOUNDED_RESOLUTION` —
so the finer reading exists internally. It is not a significant effect and should
not be promoted into one, but in an explicitly exploratory study one honest
sentence is better than smoothing it away. Something like: *the 10²¹ sample is
fully CUE-consistent; the 10¹² sample sits marginally high on every moment at
roughly two standard errors, which this design is not powered to resolve.*

For completeness, the finite-CUE control is itself displaced from the asymptotic
targets under this geometry — `μ₂` 1.32631 against 4/3, `μ₄` 3.19307 against 13/4 —
which the paper correctly states in §5.3.

## 5. What is right

The scope reduction is handled honestly: the deferred full design is preserved
rather than quietly abandoned, and `Deferred_Full_Experiment3_Record_v1.md` says
plainly that it "is deferred, not invalidated… not represented as having been
executed."

The claim boundaries hold throughout. §7.2's explicit refusal — *we do not write
"Project Montecito discovered new higher-order structure"* — is the right call, and
§6.2's demonstration that 72–80% of the raw fourth-moment displacement is
pair-driven is exactly the restraint Experiment 2 taught.

The collision decomposition is the technical heart and it is correct. The
homometric control is the conceptual heart and it is exact. Seeds derived from a
hashed pre-frozen protocol, with the hash recorded in the execution log, is
better practice than most published computational work.
